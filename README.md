### `$ whoami`

I like systems that weren't designed to be understood easily.

The interesting part isn't getting a shell. It's figuring out
why the shell was possible in the first place.

I spend most of my time somewhere between:

- Breaking web applications and enterprise environments.
- Understanding memory corruption and exploit primitives.
- Taking apart authentication protocols and trust relationships.
- Building security automation instead of repeating the same commands.
- Writing low-level software to understand what happens beneath the abstraction.

I don't particularly enjoy black boxes.
If something works, I want to know why.
If something breaks, I want to know how far it breaks.

### `$ ls -la ~/projects`

#### 01. Vulnerability Operations Center

`OpenVAS` `Wazuh` `DefectDojo` `TheHive` `Docker` `Python`

A vulnerability management pipeline connecting network scanning,
endpoint monitoring, vulnerability intelligence, and incident workflows.

```text

                        │
              Enrichment / CVSS
                        │
                        ▼
                  ┌──────────┐
                  │ TheHive  │

```

Automated scanning, centralized findings, vulnerability enrichment
through NVD/Shodan/VirusTotal, and ticket generation for
high-severity vulnerabilities.

#### 02. Active Directory Assessment Framework

`Bash` `Docker` `NetExec` `Impacket` `Certipy` `BloodHound`

An automated, containerized assessment workflow for authorized
Active Directory environments.

Enumeration, protocol-level reconnaissance, AD CS assessment,
attack-path analysis, and structured evidence collection.

Because clicking through 15 tools manually gets old.

#### 03. SecLock

`Bash` `OpenSSL` `Linux ACL` `Process Management`

Directory encryption and access-control utility.

AES-256-CBC, PBKDF2, ACL enforcement, archive management,
parallel execution, logging, and restoration.

A small project that turned into an excuse to explore
Linux processes, permissions, and cryptography.

#### 04. GamerBoy

`C` `SDL2` `CPU Emulation` `Computer Architecture`

Writing a Game Boy emulator.

Registers, instruction decoding, memory access, CPU execution,
and the beautiful inconvenience of implementing hardware behavior
in software.

**[github.com/Gastordia/gamerboy](https://github.com/Gastordia/gamerboy)**
